## 3. Copilot 裁决（2026-09-11，T-601 开工闸门）

### D1 数值结果低于最低检出限 → 视同「未检出」【裁决：采纳】
- 检验值 < `lower_limit` 时按「未检出」处理（AGENTS 7.3 规则 4 的落实）。
- 对 jt1 限量比较型：视同未检出 → **合格**（检出限必 ≤ 限量，业务上恒成立）；
  报告展示按「<检出限」或「未检出」。
- `lower_limit` 为 NULL 时不做视同，按数值正常走 jt1 比对 / D2 / D4 矩阵。

### D2 「不得检出/不得使用」型按「≥ 检出限才算检出」【裁决：采纳，最高优先级】
- jt2 判定矩阵：结果=`未检出` → **合格**；结果=数值且 ≥ `lower_limit` → 检出 → **不合格**；
  结果=数值但 < `lower_limit` → 视同未检出 → **合格**。
- `lower_limit` 为 NULL 且结果为数值 → **待判定**（无法判定是否检出，禁止默判合格）。
- 依据：20 条不合格样例反推与 GB 2763「不得检出 = 低于方法检出限」的通行解释一致。

### D3 参考性限量（is_reference=1，834 条）不计入整体结论【裁决：采纳，含补充】
- 参考项单项结论**照常计算**并在报告/详情中展示，标注「参考」（落实 AGENTS 7.3 规则 5「参与计算但标注参考」）。
- 规则 6「任一单项不合格 → 整体不合格」中的「单项」**仅指非参考项**；参考项不合格不触发整体不合格。
- 补充：若样品全部项目均为参考项，整体结论 = **待判定**（交人工），禁止自动判合格。

### D4 `--`（无判定依据）且检出限 NULL → 待判定【裁决：采纳，补全矩阵】
- stdValue=`--` 完整矩阵：结果=`未检出` → **合格**（实测口径）；结果=数值且 < `lower_limit`
  → 视同未检出 → **合格**；结果=数值且 ≥ `lower_limit`，或 `lower_limit` 为 NULL 无法视同
  → **待判定**（报告实测值，人工确认）。

### D5 从旧 prj_detail 反向回填 lib 的 jt2/jt3【裁决：采纳，T-401 一次性订正】
- 在 **T-401** 由 GLM 做**一次性数据订正脚本**（不做运行时回写）：按 stdValue 文本形态重判
  `judge_type`（含「不得检出/不得使用」→ 2；非数值纯文本 → 3），脚本须输出 before/after 分布统计。
- 判定引擎运行时**只读 `product_lib_item.judge_type`**，禁止依赖旧 `prj_detail`。

### 附：说明书两处矛盾样例【裁决：确认为旧系统数据瑕疵】
- 说明书第 2 页演示：①铅 0.1 对 `≤0.25` 判不合格；②氯霉素「未检出」判不合格。
