> 本文为 T-601 自动判定引擎的**唯一口径依据**；白名单闭集之外的输入一律 default → 待判定 + 日志。

## 1. 实测数据形态（GLM 2026-09-11 实测，裁决的事实基础）

- `product_lib_item` 3728 条：`judge_type` **全为 1**（限量比较；无 jt2/jt3）、`std_value` 100% 纯数值、
  `is_reference=1` 834 条、`lower_limit` 有值 1032 条、`basis_code` 唯一值 GB 2763-2021。
- 旧 `prj_detail` 463 条：`stdValue ∈ {数值, 不得检出, --}`、`jyResult ∈ {数值, 未检出}`、
  `item_evaluate` 合格 441 / 不合格 20 / NULL 2。
- 口径反推（据 20 条不合格样例）：`不得检出` + 数值结果 → 不合格；`10` + `10.01` → 不合格；
  `--` + `未检出` → 合格。即**「检出」= 数值结果 ≥ 最低检出限**，非字符串比对。

## 2. 白名单闭集（只认以下形态，其余 default）

- **stdValue 5 形态**：①纯数值（限量比较）②`≤数值` ③`不得检出` ④`不得使用` ⑤`--`（无要求）。
  文本/感官型（judge_type=3）不走表达式，检验员人工选合格/不合格（AGENTS 7.3 规则 3）。
- **testValue 2 形态**：①数值 ②`未检出`。
- **输出 3 形态**：`合格` / `不合格` / `待判定`。
- **default 规则**：白名单外任意组合 → `待判定` + 记日志，**禁止静默判合格**。

## 3. Copilot 裁决（2026-09-11，T-601 开工闸门）

### D1 数值结果低于最低检出限 → 视同「未检出」【裁决：采纳】
- 检验值 < `lower_limit` 时按「未检出」处理（AGENTS 7.3 规则 4 的落实）。
- 对 jt1 限量比较型：视同未检出 → **合格**（检出限必 ≤ 限量，业务上恒成立）；
  报告展示按「<检出限」或「未检出」。
- `lower_limit` 为 NULL 时不做视同，按数值正常走 jt1 比对 / D2 / D4 矩阵。

### D2 「不得检出/不得使用」型按「≥ 检出限才算检出」【裁决：采纳，最高优先级】
- jt2 判定矩阵：结果=`未检出` → **合格**；结果=数值且 ≥ `lower_limit` → 检出 → **不合格**；
  结果=数值但 < `lower_limit` → 视同未检出 → **合格**。
- `lower_limit` 为 NULL 且结果为数值 → **待判定**（无法判定是否检出，禁止默判合格）。
- 依据：20 条不合格样例反推与 GB 2763「不得检出 = 低于方法检出限」的通行解释一致。

### D3 参考性限量（is_reference=1，834 条）不计入整体结论【裁决：采纳，含补充】
- 参考项单项结论**照常计算**并在报告/详情中展示，标注「参考」（落实 AGENTS 7.3 规则 5「参与计算但标注参考」）。
- 规则 6「任一单项不合格 → 整体不合格」中的「单项」**仅指非参考项**；参考项不合格不触发整体不合格。
- 补充：若样品全部项目均为参考项，整体结论 = **待判定**（交人工），禁止自动判合格。

### D4 `--`（无判定依据）且检出限 NULL → 待判定【裁决：采纳，补全矩阵】
- stdValue=`--` 完整矩阵：结果=`未检出` → **合格**（实测口径）；结果=数值且 < `lower_limit`
  → 视同未检出 → **合格**；结果=数值且 ≥ `lower_limit`，或 `lower_limit` 为 NULL 无法视同
  → **待判定**（报告实测值，人工确认）。

### D5 从旧 prj_detail 反向回填 lib 的 jt2/jt3【裁决：2026-09-11 经 T-905 修订】
- **原裁决（已被证伪）**：曾据「lib 的 judge_type 全 1 而旧数据存在 jt2 形态」推断迁移漏迁，要求在 T-401 做一次性订正脚本回填 jt2/jt3。
- **T-905 实测（GLM，证据见 docs/knowledge/2026-09-11-adjudication-request-d5.md）**：`product_lib_item` 3728 行 `std_value` 100% 纯数值（含 `*` 参考标记），源表旧 `lib` 同样 100% 纯数值（非漏迁）；`prj_detail` 的 220 条 `不得检出` 仅 5 个兽残项目名，与 `lib`（仅农残 GB 2763-2021）**不同源**，0/5 匹配。即 judge_type 全 1 是**正确值**，无行可订正。
- **修订裁决（采纳 R1）**：V3 脚本定位从「数据订正」改为**可重跑的口径校验器**（`db/migrations/V3__correct_product_lib_item_judge_type.sql`），当前零变更即「jt2/jt3=0 是数据事实」的存档证据；标准库将来扩充（如补兽残标准）后重跑即可归一化。**硬性要求：校验器必须 fail-loud**——若「形态应然 ≠ judge_type 实然」且 UPDATE 后仍不一致，须报错退出，禁止静默通过。
- **R3（从 prj_detail 反建兽残标准库）：否决，不开任务。** 标准库的权威来源是标准文本而非历史检验记录，反建行缺 basis_code/方法/限量值，不能用于正式判定。5 个兽残项目仅登记为**已知数据覆盖缺口**；将来业务需要时由业务方提供标准文本走基础数据补录（/api/base 域 + 重跑 V3）。
- **引擎依赖（追认 T-401 强化）**：判定引擎**只读 `sample_item`（快照下沉字段），禁止回溯 `product_lib_item` / `prj_detail`**——本表述取代原 D5「只读 product_lib_item.judge_type」，语义更强（国标更新不追溯篡改已出报告）。

## 4. 对 T-601 实现的强制要求

1. 引擎入口先按 `judge_type` 分派（1 表达式 / 2 表达式 / 3 人工），表达式内再按第 2 节闭集匹配。
2. 单项结论只能由引擎生成，检验员不可手改；前端不得自算结论（AGENTS 0.2）。
3. 单元测试必须以**构造数据**（直接造 `sample_item` 行，不走标准库匹配）覆盖：jt2「不得检出」矩阵
  （数值 ≥/< 检出限、检出限 NULL）、D1 视同未检出、D4 `--` 矩阵、全参考项样品整体待判定；
  default 分支须有日志断言。**jt2/jt3 分支必须保留并有单测**——当前生产数据触发不到 ≠ 可删除，
  它们是标准库扩充后的既定语义（T-905 裁定）。旧 `prj_detail` 的 20 条不合格样例可作为构造数据的
  参照蓝本，但不要求回放真实行。
