## 1. 增量背景与目标

**背景（一段话）**：昨天的助手已能"答业务问题 + 检索已入库标准"，但它**只被动响应**、**只在被问标准时才查**、**不知道用户在流程哪一步**；今天实测又暴露两个硬约束 —— 用户给的 GB 2763-2021 是**纯扫描件（67MB / 422 页 / 每页一张 1240×1753 JPEG / 无字体无文字层）**，现有导入通道（PDF 显式拒收）**消化不了**，必须走 OCR；而 OCR 必然出错字，且这是**食品中农药最大残留限量**标准，数值抄错即资质事故（有利事实：**该标准农残限量数值已在本系统 `product_lib_item` 中**）。本次增量要在不触碰「`JudgeEngine` 唯一判定权威 + 审计流水不可篡改」两条底线的前提下，把助手从"问答工具"升级为"**懂上下文、能主动、能带路**的业务助手"，并给扫描件标准一条**可信度边界明确**的入库路径。

**可衡量目标（均需可举证）**

- **G1 主动有度**：在含**明确检测项目名**（如"铅""毒死蜱"）的业务上下文中，助手**不打断地主动提示**命中率 ≥ 90%、**误报率（上下文无项目名也主动提示）= 0**；单会话对同一项目重复提示 ≤ 1 次（举证：交互日志 + 抽样评审）。
- **G2 带得动**：覆盖 ≥4 类角色，从「我要做 X」出发给出**可点击跳转的分步 checklist**；**每步入口与该角色权限一致（越权入口 = 0 个）**；实测按引导走通率 ≥ 90%（举证：引导日志 + 实测走查）。
- **G3 事实稳定**：同一「当前状态 + 角色」的下一步提示**重复询问 ≥ 10 次，事实字段（状态 / 下一步 / 入口 / 权限）100% 一致**；涉及标准的回答 **100% 带标准号 + 出处**（举证：重复问答比对）。
- **G4 红线守得住**：所有来自 OCR 的引用卡片 **100% 标注"扫描件 / 可能有识别误差"**，且涉及数值时 **AI 的断言式数值输出 = 0**（一律指向 `product_lib_item`）；422 页扫描件可完成导入、**逐页可见进度与失败项、可重试**（举证：卡片抽样 + 任务详情）。
- **G5 不代操作**：助手产生的**写操作（建样品 / 提交 / 审核 / 签发 / 回退 / 填值提交）= 0 次**，只产生**跳转（读）**动作（举证：动作审计 + 操作日志）。

## 2. 关键设计取向（张力裁决）★ 本次 PRD 核心

### TA 「自动查询对应标准」的触发与边界

- **选定：上下文触发的"标准伴随查询"——被动优先，主动受限、低强度、带频控。**
  - **触发条件（必须可判定）**：当前业务上下文（页面上 / 对话里）**已出现明确检测项目名**，且该项目在本系统 `product_lib_item` 中**能查到对应判定依据标准号**。→ 不"猜用户想问什么"，只判断"用户正在看的东西里有没有标准可引用"。
  - **强度分级**：① 用户显式问 → 完整回答 + 引用卡片；② 用户没问但上下文命中 → 悬浮窗呈现**一行"建议条"**（如「本条涉及 GB 2763-2021，查看对应限量」），**默认折叠、不自动展开会话、不遮挡操作区**，用户点了才展开。
  - **闭嘴条件**：上下文无明确项目名 / 标准号时**不主动**；同一项目同一会话**只在首次提示一次**；用户关闭一次后本会话对该项目**静默**。
- **红线（承接上轮 T3）**：自动查到的条文**只能是建议性引用**（带标准号 + 条款 + 出处），**绝不自动判定、绝不自动填值、绝不写任何业务字段**；判定权威永远是 `JudgeEngine`。
- **排除的备选**：① *完全主动扫描式推荐* —— 变噪音，且"系统替用户决定他在问什么"在资质系统里越权观感强；② *完全被动（不问不查）* —— 直接违背用户"自动查询"原话；③ *自动把限值填进录入框* —— 触碰 T3 红线。

### TB 「业务全流程辅助 + 指导完成整套操作」的形态

- **选定：两种形态并存、职责分明 —— 以「上下文感知的下一步提示」为主，以「对话式分步引导」为辅。**
  - **下一步提示（主）**：由前端把**当前页面上下文**（样品号 + 当前状态码 + 当前角色）随消息带入，助手用**确定性映射**回答「你在第几步 / 下一步能做什么 / 入口在哪」。
  - **分步引导（辅）**：用户说「我要登记一个新样品」→ 助手给出该角色的**分步 checklist**，每步带**一键跳转入口**。
- **"怎么知道用户在哪一步"**：不靠助手"猜页面"，而由**页面把上下文显式带入**（沿用既有 `context` 字段的既有能力，仅扩充语义：补 `pageKey` / `roleCode`）。
- **"怎么不变成第二个菜单 / 文档站"（三条硬要求）**：① 回答必须落到**可点击跳转入口**，不是纯文字说明书；② 以「**下一步该做什么**」为主语，不是「这个模块有哪些功能」；③ 引导到**具体按钮 / 字段级**（"在检验数据录入页选中该样品，点『录入结果』"），不是"请前往 XX 模块"。
- **排除的备选**：① *纯对话百科* —— 就是文档站，用户明确不要；② *纯静态帮助中心* —— 无法感知状态；③ *让模型自由生成流程步骤* —— 违反 TF（见下）。

### TC 助手能不能"替我做操作"

- **裁决：不做代操作。助手只做「定位入口 + 说清填什么 + 一键跳转」，所有写操作由用户本人在目标页面发起并确认。**
- **理由**：① LIMS 出 **CMA/CATL 报告**，写操作的**责任主体必须是有对应权限的自然人**；② 助手是**跨页面悬浮窗**，若代操作会**绕过业务页面的权限显隐与二次确认**，与既有安全模型（AGENTS 8.4「前端隐藏即安全是错的、后端兜底」）冲突，等于新增一个"非业务页面的写入口"，**扩大攻击面**；③ 审计口径要求「**操作人 = 责任人**」，代操作会让 `sys_operation_log` 无法回答"到底是谁做的"。
- **允许的边界动作**：**跳转导航**（只打开页面，读安全）✅；**只读限值提示**（放在输入框旁做旁注）✅；**代填输入框** ❌；**提交 / 审核 / 签发 / 回退** ❌。
- **排除的备选**：*"低风险操作可代做"* —— "低风险"界定会陷入长期争议，且资质系统里不存在真正意义上的低风险写操作。

### TD OCR 的现实约束怎么落到产品上

- **现实**：GB 2763-2021 为**纯扫描版**（每页一张 JPEG、无字体无 ToUnicode、文字层为零）；现有通道（TXT/MD/HTML/CSV + PDF 显式拒收）**消化不了**，必须 OCR。
- **裁决一 — OCR 是「离线预处理 + 异步导入」，不进对话**：OCR 是长任务（分钟~十几分钟级），产品上以**导入任务**表达 —— `排队中 / 进行中（页码或百分比）/ 已完成 / 部分失败（列出失败页）/ 可重试`。**对话界面里不跑 OCR**。
- **裁决二 — 用途边界（本案关键）**：OCR 文本**只用于「条文引用与定位」**（找到"某项目在哪张表、哪条、大致原文"）；**数值一律以系统标准库 `product_lib_item` 为准**。产品上强制表达为：① 引用卡片**必须标注来源类型**：`文本版` / `扫描件 OCR（可能有识别误差）`；② 来自 OCR 的卡片**必须带显式提示**「本条来自扫描件识别，**数值请以系统标准库为准**」；③ 涉及数值时**不给断言式结论**，改为「该数值请在系统标准库中核对」+ **指向 `product_lib_item` 对应记录的可点击入口**。
- **裁决三 — 并行路径**：向用户明确给出「**换一份文本版 PDF**」作为**并行且更优**的路径（文本版直接走既有通道、**无 OCR 误差**）。两条路都保留：文本版是**首选**，OCR 是**现实兜底**。
- **排除的备选**：① *OCR 结果直接当权威正文、被引用为数值来源* —— 资质事故级；② *拒绝扫描版、只等文本版* —— 用户已明确给出该文件，且现实就是扫描版；③ *把 422 页 OCR 塞进对话交互* —— 时长与失败率都不适合对话。

### TE 权限与越界

- **裁决：讲流程可以，讲入口要按权限收敛，涉及越权要明说「需要什么权限、找谁开」，不诱导越权。**
- **具体口径**：① 检验员问「怎么审核报告」→ **可以讲"审核"环节的业务含义与流程位置**（业务知识），但**不给审核入口**，改为提示「审核入口需 `report:audit` 权限，你当前角色没有；需联系 R100 / R2 开通」；② **下一步提示必须按当前登录角色可执行的操作过滤**（检验员看不到"签发"入口的跳转）；③ 助手**只读**用户权限集合（复用既有 `BusinessContextReader`），**不缓存、不越权查询、不展示超权限入口 / 数据**。
- **排除的备选**：① *一律不答越权流程* —— 检验员会搞不清流程，也违背"业务全流程辅助"；② *有问必答且给入口* —— 诱导越权，在资质系统里是合规问题。

### TF 与上一轮已定规则的一致性

- **裁决：上轮「业务域确定性作答、不调模型」在新需求下继续成立，并扩大确定性覆盖。**
- **理由**：状态机映射（S10~S90）、下一步允许操作、回退边白名单、权限标识、标准号↔项目名映射 —— 这些**都有唯一正确答案**；交给 4B 模型只会带来"同一问题两次答案不同"的可靠性问题。**能确定性回答的一律不交给模型。**
- **边界扩展（事实层 / 措辞层分离）**：**事实层**（状态 / 下一步 / 入口 / 权限 / 标准号）**必须由后端确定性数据注入**；**措辞层**（把确定性结果讲成人话 / 补充解释）**可用模型润色**，但**不得生成或改写任何事实字段**。
- **排除的备选**：① *全流程引导整体交给模型生成* —— 不可靠 + 事实幻觉；② *完全不用模型* —— 用户要"能帮我做完"，需要自然语言解释能力。

## 3. 用户故事（每特性 ≥3 条，覆盖 6 类角色中 ≥4 类）

**F1 自动查标准（TA）**
- 作为**检验员（njsa000 / njna000 / njxa000）**，我在录「毒死蜱」结果时，希望助手**不用我问**就在悬浮窗提示"本条涉及 GB 2763-2021"且可点开看限量出处，以便不离开页面就能核对。
- 作为**样品登记员（nj002）**，我希望助手**只在我真正在看某项目时才提示标准**、不刷屏，以便不打扰登记。
- 作为**审核签发人（nj001）**，我希望助手的标准引用**都带标准号与条款出处**，以便判断依据，但**它不替我判定**。

**F2 全流程引导（TB）**
- 作为**样品登记员（nj002）**，我说"我要登记一个新样品"，希望助手给出**分步 + 每步跳转入口**，以便照着走完。
- 作为**任务管理员（nj003）**，我希望助手根据当前样品状态告诉我"在 S30，下一步做任务安排，入口在这里"，以便少问同事。
- 作为**检验员（njsa000）**，我希望助手告诉我"现在在 S40，下一步去录入结果"并能一键跳过去，以便不迷路。
- 作为**管理员（R100）**，我希望助手能解释"从登记到出报告的完整链路分几步、各由谁负责"，以便给新同事做 onboarding。

**F3 扫描件标准入库（TD）**
- 作为**业务管理员（R2）**，我把 422 页扫描版 GB 投进去后，希望看到**逐页进度与失败项、可重试**，以便知道这批到底进没进。
- 作为**审核签发人（nj001）**，我希望凡来自扫描件的引用**都显式标注"可能有识别误差、数值以系统库为准"**，以便我不会误用。

**F4 权限收敛（TE）**
- 作为**检验员（njsa000）**，我问"怎么审核报告"时，希望助手讲清流程但明确告诉我"你没这个权限、找谁开"，以便走对路而不是碰壁。
- 作为**管理员（R100）**，我希望助手**绝不向低权限用户展示超权限入口**，以便权限边界不被绕过。

**F5 收尾与实测（①②⑤）**
- 作为**用户（实测者）**，我希望一条命令**把后端 + 前端 + AI 服务拉起来并自检就绪**，以便直接开始实测。
- 作为**用户**，我希望看清"AI 就绪 / 模型就绪 / 标准索引就绪"三项状态，以便判断能不能开始测。

| C-10 | **文本版 PDF 并行建议路径** | P1 | 导入扫描件时明确提示"可改用文本版、无识别误差"；文本版可走既有通道完成（举证：提示文案 + 导入演示） |
| C-11 | **一键启动 + 三项就绪自检**（供实测） | P0 | 一条命令拉起后端 / 前端 / AI；三项就绪状态可查；任一不就绪给出**具体下一步指引**（举证：启动演示 + 状态页） |
| C-12 | **助手会话 / 建议条留痕可审计** | P1 | 可查「谁 / 何时 / 上下文是什么 / 主动提示了什么 / 是否被点开」，供事后追溯（举证：留痕查询） |

## 5. 交互设计说明（文字）

**自动查标准的呈现位置与强度（C-01）**
- **位置**：悬浮窗**头部下方的一条"建议条"**（单行，高对比、弱模糊，遵守 AGENTS 5.1 数据密集区红线）；**不覆盖业务操作区、不弹窗、不改页面布局**。
- **强度**：默认**折叠**，仅一行文案 + "查看"按钮；**不自动展开会话、不自动聚焦输入框**。点"查看" → 展开引用卡片 → 卡片标注来源类型与「AI 建议，仅供参考；判定以系统规则为准」水印。
- **频控**：同项目同会话只提示一次；用户关闭后本会话对该项目静默；输入框获得焦点时不插入任何内容。

**全流程引导的形态与入口（C-03 / C-04）**
- **入口**：① 悬浮窗输入框的自然语言入口（"我要登记新样品"）；② **页面上下文自动带入**（打开某样品详情时，助手默认显示该样品"在 Sxx、下一步做 X"）。
- **形态**：输出 = **结果块 + 入口块**。结果块讲"现在在哪、下一步做什么、为什么"；入口块是**可点击按钮**，点按**跳到目标页面并高亮对应操作**（一键跳转，不代填、不代提交）。
- **分步 checklist**：以"步骤 1/2/3"列出该角色完整链路，**当前步高亮、后续步灰显**，每步带入口；**步骤由后端确定性数据驱动**。

**进度 / 失败态（C-07）**
- OCR / 导入以**任务卡片**呈现：`排队中 → 进行中（第 N/422 页，百分比） → 已完成 / 部分失败`；失败卡片列出**失败页清单**并给"重试"按钮；进行中**可离开页面**（后端异步），回来仍可查。
- **失败不吞**：失败项**必须可见**（fail-loud），不静默丢弃；重试只重跑失败部分。

**与现有悬浮窗三态（收起 / 展开 / 会话）的关系**
- **收起态**：保持现状（右下角常驻图标）；**新增**在有建议条待展示时加**不打扰的小角标**，不自动展开。
- **展开态**：新增"建议条"区域（输入框上方）；原有结果区不变。
- **会话态**：新增**引导卡片**与**引用卡片来源标签**（文本版 / 扫描件 OCR）；原有引用卡片能力不变。
- **风格一致**：延续 `Aurora Glass` 与 `--lims-*` 令牌；建议条 / 卡片用 `--lims-layer-elevated` + `--lims-shadow-pop`；强调色只做描边 / 光晕；动效 ≤ 0.45s 且尊重 `prefers-reduced-motion`。

## 6. 范围（In Scope / Out of Scope）

**In Scope**
- 上下文触发的标准伴随查询（建议条 + 频控 + 引用来源标注）。
- 确定性驱动的「下一步提示 + 分步引导 + 一键跳转」（含角色权限收敛）。
- 扫描版 PDF → OCR 异步导入通道 + 进度 / 失败 / 重试。
- 数值以系统标准库为准的引用边界与对齐入口。
- 事实层 / 措辞层分离。
- 一键启动与三项就绪自检（供用户实测）。

**Out of Scope（逐条给理由）**

| 不做 | 理由 |
|---|---|
| **助手代用户执行写操作**（建样品 / 提交 / 审核 / 签发 / 回退） | 出 CMA/CATL 报告的责任主体必须是**有权限的自然人**；代操作绕过页面权限与二次确认、扩大攻击面、破坏「操作人=责任人」审计口径（见 TC）。 |
| **OCR 数值直接用于判定 / 直接填值 / 作为数值权威来源** | GB 2763-2021 是农残限量，OCR 出错字即资质事故；数值一律以 `product_lib_item` 为准（见 TD 及上轮 T3 红线）。 |
| **助手自动判定合格 / 写结论字段** | 违反上轮 T3 与 `JudgeEngine` 唯一权威，**红线**。 |
| **把 422 页 OCR 放进对话交互里跑** | 长任务 + 失败率不适合对话，改为异步导入任务（见 TD）。 |
| **全流程引导整体交给模型生成** | 状态 / 入口 / 权限有唯一正确答案，模型生成会"同问不同答"（见 TF）。 |
| **自动扫描全页面猜用户想问什么** | 噪音大、越权观感强；改为"上下文已出现项目名"这个可判定触发（见 TA）。 |
| **对低权限用户展示超权限入口** | 诱导越权，资质系统合规问题（见 TE）。 |
| **内置 / 预置 GB 标准正文** | 版权 + 体积；仍只交付导入通道（沿用上轮 T2）。 |
| **为助手引入 Markdown 重渲染依赖** | 沿用上轮结论：用结构化文本 + 引用卡片，不引渲染库。 |
| **新建独立「帮助中心 / 文档站」** | 用户明确要"能帮我做完"而非"再读一遍说明书"（见 TB）。 |
