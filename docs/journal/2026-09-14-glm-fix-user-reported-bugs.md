# 2026-09-14 GLM 修复轮：用户实测反馈的 4 类问题

## 一、本轮目标

用户以 R3「水产检验员」等账号实测后反馈（原话要点）：

> 「各种下载的报告任务什么的都在哪里；登 R3 开头界面就是**业务概览加载失败**，没有权限也不需要这样报错显示；
> 点**查看质量分析也是 404**；然后**录入数据也没有录入的地方，录不了**；其他账号也要关注这种情况；
> 如下载导入模板是空页面、**下载模板没有响应**；生成的那些报告也生成不了，等等都操作不了。」

因此本轮是 **Bug 修复轮**（非新功能），目标是把「用户点得动、看得懂、有活干」三个层面都补齐。

## 二、诊断：先把「真缺陷」和「数据缺口」分开

做法：把 6 个账号逐一带 token 跑一遍**它们各自菜单对应的接口**（脚本按菜单 path → 该页首屏接口映射），
再用 Edge + CDP 复现用户操作路径。

| # | 现象 | 根因 | 定性 |
|---|---|---|---|
| 1 | R3 工作台弹红错「业务概览加载失败」 | 工作台**无条件**调 `/stat/overview`（需 `stat:view`），R3 无此权限 → 403 被当成错误 | **代码缺陷** |
| 2 | 点「查看质量分析」→ 404 | Hero 区两个按钮**硬编码跳转**，未做权限判断；无权限页未注册 → 命中 catch-all 404 | **代码缺陷** |
| 3 | 下载导入模板「空页面、没响应」 | `<el-link target="_blank">` + dev server 对 `.xlsx` 返回**空 Content-Type** → 浏览器开新标签后什么都不做 | **代码缺陷** |
| 4 | R3「录入数据没有地方、录不了」 | 库存数据里**没有任何样品处于 S40/S50**（样品 1 已走完 S90，样品 2 停在 S20）→ 列表为空 | **数据缺口** |
| 5 | 「生成的那些报告也生成不了」 | 库里**没有 S80（已签发待生成）样品**，两条都是 S90 → 列表只给「重打印」；且 `POST /report/generate` 对已生成样品返回 400 是**正确**行为 | **数据缺口** |
| 6 | 「其他账号也要关注」 | 逐角色普查确认 R1/R2 同样在工作台吃 403 | 同 1、2 |

> 关键区分：**1/2/3 是代码缺陷，4/5 是「演示数据无法自测」**。
> 若把 4/5 当代码 bug 去改状态机，会把正确的约束改坏；若只说「这不是 bug」而不补数据，
> 用户依然测不了。**两者都要处理，但处理方式完全不同。**

## 三、代码修复

### 3.1 工作台权限感知（`views/dashboard/index.vue`）

```ts
const canViewStat    = computed(() => authStore.hasPermission('stat:view'))
const canViewMyTasks = computed(() => authStore.hasPermission('result:entry'))

// 只发起有权限的请求；无权限的保持 null，由中性空态表达
if (canViewStat.value)    jobs.push(getStatOverviewApi().then(...).catch(() => { overviewError.value = true }))
if (canViewMyTasks.value) jobs.push(get('/query/my-tasks/page', {...}).then(...).catch(() => { tasksError.value = true }))
```

配套三处模板调整：
- `kpis` 改为**按权限过滤**：检验员只看到「待处理任务」，不再出现一排「—」；
- 两个 Hero 按钮加 `v-if`（无权限直接不渲染，而不是点了报错）；
- 两块数据区各加一个**中性空态**（`AppEmpty`，说明缺哪个权限、去哪儿办），
  并把 `overviewError` 的语义收窄为「**有权限但真的失败了**」。

### 3.2 「页面存在但没权限」判定为 403 而非 404（`router/index.ts`）

```ts
if (to.meta.public) {
  // 回查注册表：路径确实是系统内已登记的页面 → 语义是「无权限」而不是「不存在」
  if (to.name === 'not-found' && ROUTE_BY_PATH.has(to.path)) return { name: 'forbidden' }
  return true
}
```
403 页文案同时改为可操作（「从左侧菜单进入你负责的功能；如需开通请联系管理员」）。

### 3.3 模板下载（`views/sample/index.vue`）

去掉 `target="_blank"`，改用 HTML `download` 属性：
```html
<el-link :href="TEMPLATE_URL" :download="TEMPLATE_FILENAME">下载导入模板</el-link>
```
理由：**`download` 属性在同源时忽略 `Content-Type`**，浏览器按属性值保存文件——
这正好绕开「dev server 对 .xlsx 返回空 Content-Type」导致的不响应。
不用 fetch+Blob 方案是因为静态资源不需要鉴权，原生属性更简单也更稳。

### 3.4 顶部待办面板的去 403（`layouts/MainLayout.vue`）

上一轮新加的「待办提醒」会在挂载时拉 6 个业务接口。R3 无权限的那几个会返回 403，
**在控制台留下成串 `403 Forbidden`**——正是用户说的「没权限也要报错」。
修复：给每个待办源声明 `permission`，**发请求前**过滤：

```ts
const allowed = todoSources.filter((s) => authStore.hasPermission(s.permission))
```
权限是 `/me` 已返回的前端已知信息，**没有任何理由先请求再吃 403**。

## 六、💡 心得与判断

1. **「没有权限」不是「加载失败」。** 用红色错误告警表达权限不足，用户会判定「系统坏了」——
   本次用户的反馈正是如此（「没有权限也不需要这样报错显示啊」）。
   正确姿势：**前端拿得到权限就提前判断**，无权限的部分渲染中性空态 + 替代指引。
   错误告警只应留给「有权限但真失败了」。

2. **404 与 403 是两种事实，不能混。**
   页面未注册（无权限）会命中 catch-all → 404，用户看到的是「功能不存在」。
   修法是在守卫里回查注册表，把「已登记但无权限」改判 403。**语义准确的错误页能省掉一轮沟通。**

3. **用户说「XX 用不了」时，先分清是「代码坏了」还是「没有可用的数据」。**
   本次 4 个抱怨里，2 个是数据缺口（无待录入样品、无待生成报告样品）。
   若不区分，要么把正确约束改坏，要么只回一句「数据问题」而用户依然测不了。

4. **演示数据的价值 = 让每个角色都有第一步可走。**
   一个只跑通「管理员全流程」的演示库，对「检验员登录后干什么」是零信息。
   **按角色铺待办**（每个角色至少 1 条属于自己的待办）应作为交付标准之一。

5. **前端已知的权限，不该用 403 去发现。**
   待办面板挂载即请求 6 个接口，无权限账号直接刷出 15 条控制台 403。
   权限来自 `/me`，**请求前的过滤是零成本**；靠 403 兜底既吵又掩盖真错误。

## 七、⚠️ 踩坑记录

### 坑 1：dev server 对 `.xlsx` 返回**空 Content-Type**（静态资源下载静默失效）

- **现象**：`<a href="/templates/x.xlsx" target="_blank">` 点击后开一个空白标签页，**什么都不下载**。
- **根因**：`curl -i` 显示 `Content-Type:` 为空（同目录 `favicon.svg` 却是 `image/svg+xml`）。
  dev server 的 MIME 表不认 `.xlsx`；浏览器拿不到类型 + `target="_blank"` → 不做任何处理。
- **处理**：改用 HTML `download` 属性（同源时**忽略 Content-Type**，按属性值保存）。
- **教训**：**下载类功能必须验证「真的落盘」**，不能只看链接存在。
  本次用 CDP `Browser.setDownloadBehavior` 把下载目录指到临时文件夹，再检查文件与字节数。

### 坑 2：`bash` 里用 `cat > f << 'EOF'` 写含 `${}` 的 JS 会被吃掉

写探针脚本时 `console.log(\`${x.padEnd(4)}\`)` 触发 `Bad substitution`。
**含模板字符串的脚本一律用文件写入工具**，不要走 heredoc。

### 坑 3：逐角色接口普查要按「该页首屏真实调用」建映射

第一版普查用了统一分页参数，结果 `pageNum/pageSize` 域（task/sample）全报
`缺少必填参数: pageNum` ——这是**探针的错**，不是接口的错（api-spec 0.3 已记录分页双轨）。
**普查脚本报错时先怀疑探针，再怀疑系统。**

## 九、可复用结论

1. **权限感知的工作台模式**：`hasPermission` → 条件请求 → 分区块中性空态 → 错误告警只留给真失败。
   （可直接复用到任何「多角色共用首页」的场景。）
2. **404/403 判定增强**：catch-all 命中时回查路由注册表，已登记但无权限 → 403。
3. **静态资源下载**：同源下载一律加 `download` 属性；验证标准是「文件真的落盘 + 字节数正确」。
4. **接口请求前先过权限**：前端已知权限时不该用 403 做发现（避免控制台噪音 + 掩盖真错误）。
5. **演示数据按角色铺待办**（每个角色 ≥1 条），并把「各角色的第一步操作」写进 README。
