# 2026-09-14 GLM：下载改为「可自选保存位置」

## 一、本轮目标

用户要求：**「把所有下载的地方改为可以选择下载在哪而不是固定的」**。

原先所有下载都固定落到浏览器默认下载目录（`C:\Users\<用户>\Downloads`），用户下载完不知道文件去哪了
——上一轮「下载导入模板没反应」的排查成本，很大一部分就来自这个不可见性。

## 二、实际做法

### 1. 改造统一的下载工具 `utils/download.ts`

新增 `saveBlobAs()`：走 File System Access API 的 `showSaveFilePicker()`，弹出系统「另存为」对话框。

```ts
await saveBlobAs(
  () => exportProvinceApi(...),          // ← 数据工厂函数，不是已完成的 Blob
  suggestedExportName('省平台上报数据', 'xlsx'),
  XLSX_FILE_TYPE,
)
```

**最关键的一处设计**：参数是**数据工厂函数**而不是 Blob。
因为 `showSaveFilePicker()` 依赖**瞬时用户激活态**，任何 `await` 之后即失效并抛 `SecurityError`。
用工厂函数把「取数据」延后到对话框确认之后，**从 API 形状上强制了正确顺序**——
调用方即使想写错也写不出来。

### 2. 五个页面、六处下载全部改造

| 页面 | 下载内容 | 改造方式 |
|---|---|---|
| 我的检验任务 | 检验任务 Excel | 接口 Blob → 数据工厂 |
| 结果录入 | 导出我的任务 | 同上 |
| 省平台上报 | 上报数据 Excel | 同上 |
| 样品登记 | 采样单导入模板 xlsx（静态文件） | 改为 `fetch` → blob → 另存为（两处入口共用） |
| 方法资质 | 资质导入模板 csv（前端生成） | 直接传 Blob（同步生成，不影响激活态） |
| 项目标准库 | 项目库导入模板 csv（前端生成） | 同上 |

改造后 `downloadBlob()` 仅作为 API 缺失时的兜底，页面层已无直接调用。

### 3. 三种结果都有明确反馈

```ts
saved      → 「检验任务已保存」
cancelled  → 「已取消保存检验任务」        （AbortError，不算错误）
fallback   → 「已存到浏览器默认下载目录（当前浏览器不支持「另存为」…）」
```

## 三、💡 心得与判断

1. **「必须先弹框、后取数据」不是风格偏好，是硬约束。**
   直觉写法是「先请求拿数据 → 再弹框问存哪」，但在浏览器里必然报 `SecurityError`。
   这类"顺序敏感"的 API，**最好的防御是让 API 形状无法被写错**——接受工厂函数，
   调用方就没有「先 await 再传 Blob」的机会。

2. **必须先弹框 ⇒ 拿不到服务端文件名。** 这是上一条的必然代价：
   响应头里的 `Content-Disposition` 要等请求回来才知道，而请求必须晚于对话框。
   取舍是**用带时间戳的建议名 + 允许用户改名**换「可自选位置」。
   时间戳本身也有价值：导出是"当时的数据快照"，同名覆盖会让人分不清哪次是哪次。

3. **体验增强不能变成功能前提。** 「另存为」不支持时（Firefox/Safari、或非安全上下文）
   必须静默降级为默认下载目录，**文件一定要能拿到**。
   特别注意：该 API 要求**安全上下文**——通过 `http://<内网IP>:5173` 访问时不可用，
   这是实际部署中很容易被忽略的坑。

4. **取消不是错误。** `AbortError` 单独识别，提示「已取消」，且此时**不发请求**
   （数据工厂没被调用），既省流量也不会给用户"出错了"的错觉。

## 四、⚠️ 踩坑记录

### 坑：headless 浏览器无法验证「用户激活态」语义

为验证"先弹框后取数据"的必要性，做了对照实验（点击后立即调用 vs 点击后先 `await` 再调用原生
`showSaveFilePicker`）：**两种方式在 headless 下都返回 `AbortError`**——
说明 headless 环境不会真正弹对话框，也不会执行激活态校验。

- **结论**：这类依赖用户激活态的 API **无法用无头浏览器验证**，只能靠规范约束 + 设计上不给出错的机会。
- **诚实标注**：本轮桩测试（替换 `showSaveFilePicker`）已验证「数据链路 + 写入字节 + 三种结果提示」，
  但**真实系统对话框需要人工点一次**。

## 六、可复用结论

1. **浏览器"另存为"通用封装**（含类型声明、降级、取消处理）可直接复用到任何前端项目。
2. **顺序敏感 API 的防御式设计**：把「必须先做的事」编码进参数类型（工厂函数），
   而不是靠注释提醒。
3. **无头浏览器的能力边界**：可验证 DOM/接口/桩替换后的数据流；
   **不可验证**原生系统对话框、用户激活态、真实下载落盘位置。
   写验收报告时要把「已验证」与「需人工确认」分开。
