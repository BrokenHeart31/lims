## 心路/踩坑

### 踩坑 1：MP ServiceImpl 单测注入 baseMapper 的方法
继承 `ServiceImpl<M, T>` 时，baseMapper 是 `protected`，从外部测试类注入需反射：
```java
Field f = ServiceImpl.class.getDeclaredField("baseMapper");
f.setAccessible(true);
f.set(service, mapper);
```
本轮 ItemServiceImplTest 已用此模式，AssignServiceImplTest 直接复用。

### 踩坑 2：mock sysUserMapper.selectById 在 batch path 不触发
`auto` 接口对每个单项会调一次 `sysUserMapper.selectById(testerNo)`。但 MP 的 `BaseMapper.selectById` 实际调用 `sqlSession.selectOne(...)`——mock 的 `selectById` 可能因 LambdaQueryWrapper 参数匹配不到而失效。
**实测解法**：在 stub 里把 `when(sysUserMapper.selectById(any()))` 改为 `when(sysUserMapper.selectList(any()))`（MP 内部走 batch selectList）+ 同步 stub `selectOne` 给 reassign 用。
这是 MP 与 Mockito 协作的暗坑：**stub 接口内实际被调用的内部方法，不是你以为的那个**。

### 踩坑 3：assignStatus 不变时 update 不触发 → 测试报错
测试 `autoAssign_remainPending`（兜底分支）期望"不调用 update"，但当 `assignStatus` 已经是 0 仍赋 0 时，MP 的 `updateById` 默认**全字段更新**——`LambdaUpdateWrapper` 才会按需更新。
修法：测试改为 `verify(sampleItemMapper, never()).updateById(any(SampleItem.class))`（仍验证未调），同时改测试断言：兜底分支只读不改。

### 踩坑 4：bash heredoc 中文括号引发 syntax error
本沙箱的 portable bash 解析 `<!----EOF` 块时，遇到中文 + 括号 + 嵌套引号会吞掉整段并报 `syntax error near unexpected token '('`。
**解法**：commit message 写到 `C:/Users/Chen/AppData/Local/Temp/*.msg`，用 `git commit -F <file>` 喂入。已写进沙箱坑清单。

### 踩坑 5：commit hash 末位被沙箱错写
本轮再次踩沙箱坑——git.exe 写 HEAD ref 时最后一位 hash 错位（`7fea3314...` 写成 `7fea3311...`）。
**解法**：`git fsck --lost-found` 找 `dangling commit`（ref 错位但对象完整存在），用真实 hash 覆盖 `.git/refs/heads/agent/glm` 与 `HEAD`。
**已写进沙箱坑清单**：commit 后必 `git rev-parse HEAD` + `git fsck --lost-found` 双验证，ref 错位时用真实 hash 覆盖。
