# 📔 工作日记索引（docs/journal/）

> 依据 `AGENTS.md` 第 2.5 节「工作纪律三件套」第 1 件：**每次会话必须写日记**。
>
> 日记不是流水账，只写**有判断价值**的内容：为什么这样做、排除了什么方案、哪些判断被数据推翻、踩了什么坑、有什么可复用结论。
>
> 命名：`YYYY-MM-DD-<agent>-<主题>.md`

## 为什么要有这个目录

本项目除了交付 LIMS 系统本身，还要交付**一套可复现的经验资产**：让后人以此为模板，
「一步到位」复现同类项目。代码只能回答「做了什么」，日记回答「**为什么这么做、当时怎么想的、错在哪**」——
后者才是无法从代码里读出来的部分。

## 配套技能库

本目录的「可复用结论」段应同步沉淀为 `.agents/skills/` 下的可执行技能：

| 技能 | 用途 |
|---|---|
| `lims-stage-delivery` | **业务阶段全链路交付标准流程**（验证前提 → 契约 → 建表 → 后端 → 单测 → 前端 → 门禁 → 收工三件套 → 推送） |
| `sandbox-git-push` | 沙箱内 git 提交/合并/推送的坑与规避 |
| `rbac-backend` / `mybatisplus-crud` / `vue3-crud-page` / `excel-import` | 分层实现模板 |

## 阅读建议

- 想了解**为什么某个技术选型**：查 `docs/knowledge/`（结论层），再查本目录同日日记（推理层）
- 想了解**某个坑怎么避**：搜本目录「⚠️ 踩坑记录」
- 想接手某个模块：查该模块相关日记的「可复用结论」段
