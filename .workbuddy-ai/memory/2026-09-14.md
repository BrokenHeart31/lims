## 关键判断

- **操作日志不做 AOP 而做 HandlerInterceptor**：离线 Maven 仓无 `aspectjweaver`。
  审计本质需求是「集中记录 + 零业务侵入」，拦截器同样满足。**先问需求本质，再选手段。**
- **日志权限不用 `@PreAuthorize`**：那会让普通检验员查不到自己的记录。
  改为分级数据范围（人人查自己 / `log:view` 跨用户），服务层强制。
  **权限注解解决「能不能调接口」，解决不了「能看哪些行」。**
- **「禁 mock」的边界是「一切用户可见数字」，不只是业务页面**——壳层（顶栏铃铛）最易漏。

## ⚠️ Git 踩坑（高价值）

`.git` 缺 **91 个对象**（6 commit + 多 tree/blob），`git status/branch` 直接报错。

- **`git fetch` 修不好**：本地 `refs/remotes/origin/*` 指向旧 hash，git 据此告诉远端「这些我都有了」
  → 远端不发送 → 拉完仍缺，报 `did not send all necessary objects`。
  **本地对象库损坏时，增量 fetch 会被自己的错误 ref 误导。**
- **解法**：`git clone --mirror <url> lims_recovery.git` → 拷 `objects/pack/pack-<new>.*` 回来
  → **删过期 `multi-pack-index`** → `git fsck --full` = 0 missing / 0 broken。
- **副坑**：给 `git clone` 传绝对 POSIX 路径（`/c/Users/...`）**静默什么都不做**（退出码 0、目录不存在）；
  用相对路径才成功。
- **网络判断**：`curl https://github.com` = `000`，但 `git ls-remote` 完全正常。
  **判断能否推送只看 `git ls-remote`。**
